2.  TIME AXIS AND PHASE DEFINITIONS
────────────────────────────────────────────────────────────────────────────────

FCN initial condition: 2023-02-01 00:00 UTC

Step k (k = 0, 1, …, 119):
  Valid time  = IC + k × 12 hours
  Lead day    = k × 0.5 days
  Lead day range: 0.0, 0.5, 1.0, …, 59.5

Phase definitions:
  Early phase   : lead day  0 – 29.5  (steps  0–59)
  Mature phase  : lead day 30 – 59.5  (steps 60–119)

  The early phase is where IC information still dominates. Insertions provide
  a corrected IC, so improvements are largest here.
  The mature phase is where model error saturation dominates; improvements here
  indicate correction of systematic model bias rather than IC error.

3.  LATITUDE BANDS
────────────────────────────────────────────────────────────────────────────────

Three broad dynamical bands (both hemispheres):

  Tropics       : -30° ≤ lat < 30°
  Midlatitudes  : -60° ≤ lat < -30°  OR  30° ≤ lat < 60°
  Polar         : -90° ≤ lat < -60°  OR  60° ≤ lat < 90°

Four latitude slice centres (for Figure 5.35 diagram only):
  2°N  — deep tropics / ITCZ
  14°N — subtropics / Hadley cell edge
  40°N — midlatitude storm track
  60°N — subpolar / polar front jet

Grid: 721 latitude points × 1440 longitude points
  lats_1d = linspace(90, -90, 721)  → 0.25° spacing, 90→-90
  lons_1d = linspace(0, 359.75, 1440)


────────────────────────────────────────────────────────────────────────────────
4.  COSINE-LATITUDE WEIGHTING
────────────────────────────────────────────────────────────────────────────────

Motivation: The Earth's surface element is dA = R² cos(φ) dφ dλ, where φ is
latitude and λ is longitude. Grid cells at high latitude cover less physical
area than equatorial cells at the same angular resolution. Without weighting,
polar values receive the same weight as tropical values despite representing
a much smaller area.

Weight array:
  w(φ) = cos(φ)    where φ is in radians = deg2rad(lat)
  w_2d[lat_idx, lon_idx] = cos(deg2rad(lats_1d[lat_idx]))

  This 2D weight array has shape (721, 1440).

Normalisation: weights are normalised within each band sum:
  W_band = Σ_{(i,j) in band} w_2d[i,j]

The band-weighted RMSE at each timestep uses these weights in the squared
error accumulation (see Section 5 below).


────────────────────────────────────────────────────────────────────────────────
5.  RMSE FORMULA (COSINE-LATITUDE WEIGHTED, WITHIN-BAND)
────────────────────────────────────────────────────────────────────────────────

At lead step k, for variable v, latitude band B:

  RMSE_B(k) = sqrt(  Σ_{(i,j) ∈ B}  w[i] × [FCN(k,i,j) − ERA5(k,i,j)]²
                     ─────────────────────────────────────────────────────
                              Σ_{(i,j) ∈ B}  w[i]
                   )

  Where:
    k            = timestep index (0–119)
    (i,j)        = (lat_index, lon_index)
    w[i]         = cos(deg2rad(lat[i]))
    FCN(k,i,j)   = FCN forecast value at step k, gridpoint (i,j)
    ERA5(k,i,j)  = ERA5 truth value at matching valid time, gridpoint (i,j)
    ∈ B          = sum only over lat/lon points inside band B

  The result is a scalar in the same units as the variable.

Code implementation:
  sq   = (fcn_arr - era5_arr) ** 2          # (721, 1440) pointwise squared error
  w    = cos_w_2d * lat_mask[:, None]        # zero outside band
  wsum = w.sum()                             # sum of weights in band
  rmse = sqrt((sq * w).sum() / wsum)         # weighted RMS


────────────────────────────────────────────────────────────────────────────────
6.  DERIVED VARIABLES
────────────────────────────────────────────────────────────────────────────────

Wind speed at 500 hPa:
  wind500(k,i,j) = sqrt( U500(k,i,j)² + V500(k,i,j)² )

  Computed for both FCN (channels 15 and 28) and ERA5 (shortName='u','v',
  level=500) before computing the RMSE. This is wind magnitude in m/s.

Wind speed at 10m:
  wind10(k,i,j) = sqrt( U10m(k,i,j)² + V10m(k,i,j)² )

  FCN: channels 0 and 1 (u10m, v10m)
  ERA5: shortName='10u', '10v', typeOfLevel='surface'

  Note on units: FCN u10m/v10m are in m/s; ERA5 10u/10v are in m/s.
  No unit conversion needed.

  Note: wind RMSE is computed from the derived magnitude, NOT from the u and v
  components separately. This removes sign ambiguity and measures the
  physically relevant quantity (total wind error).


────────────────────────────────────────────────────────────────────────────────
7.  PERCENTAGE IMPROVEMENT FORMULA
────────────────────────────────────────────────────────────────────────────────

For insertion run R, variable v, band B, phase P (initial or mature):

  mean_RMSE_ctrl(v,B,P) = mean over all steps k in phase P of RMSE_B_ctrl(k)
  mean_RMSE_R(v,B,P)    = mean over all steps k in phase P of RMSE_B_R(k)

  pct_improvement(R,v,B,P) = 100 × [mean_RMSE_ctrl − mean_RMSE_R] / mean_RMSE_ctrl

  Positive → insertion R improves (reduces) RMSE relative to control
  Negative → insertion R worsens RMSE relative to control
  Zero     → insertion has no effect

  Note: this uses the time-mean RMSE within the phase, not the phase-endpoint RMSE.
  This gives a more robust estimate that is not sensitive to RMSE oscillations
  at any single timestep.


────────────────────────────────────────────────────────────────────────────────
8.  ERA5 TIME MATCHING ALGORITHM
────────────────────────────────────────────────────────────────────────────────

FCN steps occur at 12-hourly intervals; ERA5 reanalysis is 6-hourly.
Every FCN valid time has an exact ERA5 match (since 12h is a multiple of 6h).

Algorithm:
  For each FCN step k with valid time t_k:
    1. Load ERA5 array (N_time, 721, 1440) for the relevant month
    2. Compute time differences: δt = |ERA5_times - t_k|
    3. Find idx = argmin(δt)
    4. If δt[idx] ≤ 1 hour: accept ERA5[idx, :, :] as truth for step k
       Else: mark step k as ERA5-unavailable (NaN in RMSE array)

  Since ERA5 files cover full months and FCN valid times land on 00:00 and
  12:00 UTC, all 120 FCN steps should have an exact ERA5 match (δt = 0).

  Processing order to minimise RAM: load one month at a time, extract
  matching steps, delete monthly array, move to next month.

Figure 5.37 — Wind-Insertion Lat-Band RMSE Time Series (T500 and Z500)
─────────────────────────────────────────────────────────────────────────────
Same layout as 5.36, but focus run = Wind-insertion (blue, dashed, thick).
Variables: T500 (row 0), Z500 (row 1).

What it probes:
  Row 0 (T500): Does wind correction propagate back to temperature?
    The advection equation: ∂T/∂t ≈ -u·∇T − ω·∂T/∂p + Q/Cp
    Horizontal temperature advection (-u·∇T) is directly corrected when u is
    corrected. Expect midlatitude T500 improvement from Wind-ins.

  Row 1 (Z500): Does wind correction improve the mass field?
    Via geostrophic balance: ∂Z/∂t includes geostrophic advection.
    Correct winds → correct mass advection → reduced Z500 error.

─────────────────────────────────────────────────────────────────────────────
Figure 5.38 — Z-Insertion Lat-Band RMSE Time Series (T500 and Wind500)
─────────────────────────────────────────────────────────────────────────────
Same layout, focus run = Z-insertion (orange, dashed, thick).
Variables: T500 (row 0), Wind500 (row 1).

What it probes:
  Row 0 (T500): Does Z500 correction cascade to temperature?
    Hypsometric: T̄_layer = (g/R) × ΔZ / ln(p_low/p_high)
    If Z-ins corrects T500 across all bands → FCNv2 implements hypsometry globally.

  Row 1 (Wind500): Does Z500 correction cascade to winds?
    Geostrophic: u_g = -(g/f)∂Z/∂y, v_g = (g/f)∂Z/∂x
    At low latitudes f → 0 so geostrophic wind diverges. Expect WEAKER
    Wind500 correction from Z-ins in tropics vs midlatitudes.

11.  WHAT EACH VALUE TELLS YOU
────────────────────────────────────────────────────────────────────────────────

Time-series RMSE value at day 30, Midlatitudes, Z500, Control:
  Interpretation: On average, 30 days after IC, FCNv2's Z500 in the
  midlatitude band has an area-weighted RMS error of this many m²/s²
  relative to ERA5 truth. A value of ~1000 m²/s² corresponds to ~100 m
  geopotential height error, which is meteorologically significant
  (synoptic scale weather systems have amplitudes of 100–300 m).

Time-series RMSE value at day 30, Midlatitudes, T500, T-insertion:
  Interpretation: After inserting ERA5 T500 truth into FCNv2 at every step,
  the residual T500 error in the midlatitudes at day 30 is this many K.
  If this is similar to the control value: T-insertion in the initial phase
  doesn't help T500 in the midlatitudes long-term (expected — corrections decay).

Pct improvement = 8.5%, Z-insertion, Midlatitudes, T500, Mature phase:
  Interpretation: In the mature phase (day 30–60), Z-insertion reduces
  the mean T500 RMSE in the midlatitude band by 8.5% compared to the
  control run. This means the geopotential insertion is correcting a
  systematic T500 bias that persists throughout the mature phase.

Negative pct improvement = -3.2%, T-insertion, Polar, U500, Early phase:
  Interpretation: T-insertion WORSENS polar U500 by 3.2% in the early phase.
  This indicates "analysis shock" — inserting corrected T500 creates
  imbalances (e.g., ageostrophic circulations) that temporarily degrade U500
  in the polar band where the model's dynamical balances are more sensitive.

12.  TROUBLESHOOTING NOTES
────────────────────────────────────────────────────────────────────────────────

ERA5 GRIB loading with cfgrib:

  Pressure-level variables:
    filter_by_keys = {
        "typeOfLevel": "isobaricInhPa",
        "level": 500,
        "shortName": "t"  # or "u", "v", "z"
    }

  Surface variables (10m wind):
    filter_by_keys = {
        "typeOfLevel": "surface",
        "shortName": "10u"   # or "10v"
    }
    Note: ERA5 surface 10m wind is stored as typeOfLevel='surface', level=0
    in GRIB format (NOT 'heightAboveGround', level=10 as one might expect).

  Scalar coordinate removal (required before xr.concat across months):
    drop_list = [c for c in ds.coords
                 if ds.coords[c].dims == ()
                 or c in ('step','number','isobaricInhPa','surface','valid_time',
                          'heightAboveGround')]
    ds = ds.drop_vars(drop_list, errors='ignore')

  TimedeltaIndex indexing (common error):
    deltas = np.abs(era5_times - target_time)  → returns TimedeltaIndex
    idx = deltas.argmin()
    deltas[idx].total_seconds()   # ← correct (square bracket indexing)
    deltas.iloc[idx]              # ← WRONG — TimedeltaIndex has no .iloc

FCN h5py loading:
    with h5py.File(path, "r") as f:
        arr = f["prediction"][:, channel_idx, :, :]   # (120, 721, 1440)
    Memory: 120 × 721 × 1440 × 4 bytes ≈ 499 MB per variable per run

  Process one run at a time; del and gc.collect() between runs.

ERA5 latitude orientation:
    ERA5 GRIB lat is 90→-90 (descending) by default.
    FCNv2 grid: linspace(90, -90, 721) → also 90→-90.
    Flip check: if lat_vals[0] < lat_vals[-1]: da = da.isel(latitude=slice(None,None,-1))
    This ensures consistent N-to-S orientation before comparison.
